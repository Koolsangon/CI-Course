먼저, 큰 그림을 봅시다

명령어를 외울 필요는 없습니다. 지금 우리가 무엇을, 왜 하는지 흐름만 잡으면 나머지는 복사·붙여넣기로 따라올 수 있습니다.

이 프로젝트는?  LG Display CI(원가혁신) 과정 교육생이 개발원가 계산을 게임으로 익히는 웹 시뮬레이션입니다. 우리가 만질 코드는 이 웹사이트이고, 최종 목표는 고친 내용을 실제 라이브 사이트에 반영하는 것입니다.

이번에 익히는 5개의 동작

아래 다섯 가지가 전부입니다. 각각이 뒤 섹션의 한 단계와 1:1로 연결됩니다.

계정과 도구를 준비한다
GitHub·Claude에 가입하고, 컴퓨터에 Git·Node·Claude Code를 깐다. 딱 한 번만 하면 됩니다.
프로젝트를 내려받는다 clone
GitHub라는 클라우드 창고에 보관된 코드 전체를 내 컴퓨터로 복제합니다.
내 컴퓨터에서 실행해 본다 npm run dev
고치기 전에, 사이트가 내 컴퓨터에서 잘 뜨는지 눈으로 확인합니다.
Claude Code로 고치고 점검한다
AI에게 한국어로 "이렇게 바꿔줘"라고 부탁하면 코드를 수정해 줍니다. 그 뒤 빌드로 이상 없는지 확인합니다.
올리면 자동으로 배포된다 push
고친 내용을 GitHub에 올리면(push), AWS가 알아서 라이브 사이트에 반영합니다.

먼저 알아둘 용어 8개

GitHub
코드를 보관·공유하는 클라우드 창고. 여기에 프로젝트가 저장돼 있습니다.
Git
내 컴퓨터에서 코드 변경 이력을 관리하는 도구. GitHub와 짝꿍입니다.
clone
창고의 프로젝트를 통째로 내 컴퓨터에 복제(처음 1회).
pull
창고의 최신 변경분만 내 컴퓨터로 당겨받기(작업 전마다).
commit
내 변경을 "한 묶음"으로 저장하며 설명을 붙이는 것.
push
내 commit을 창고(GitHub)로 올리기. 여기서 자동 배포가 시작됩니다.
빌드 build
사람이 쓴 코드를 브라우저가 실행 가능한 형태로 변환·검증.
Claude Code
터미널에서 한국어로 부탁하면 코드를 읽고 고쳐주는 AI 도우미.
💡터미널이 뭐죠?

까만 화면에 글자로 명령을 입력하는 창입니다. Windows에서는 PowerShell이 그 역할을 합니다. 시작 메뉴에서 PowerShell을 검색해 실행하면 됩니다. 이 가이드의 까만 코드 상자는 전부 이 PowerShell 창에 붙여넣는 명령입니다. (상자 오른쪽 복사 버튼을 누르면 편합니다.)

01

GitHub 가입 & 권한 받기

약 10분

코드 창고에 들어갈 출입증을 만드는 단계입니다. 그리고 우리 프로젝트에 글을 쓸 수 있는 권한까지 받습니다.

1.1계정 만들기

  1. github.com/signup 접속
  2. 이메일 → 비밀번호 → 사용자 이름(username) 순서로 입력. 이 username은 동료들에게 알려줄 이름이니 적어두세요.
  3. 가입 이메일로 온 인증 코드를 입력하면 완료.
📝적어둘 것

내 GitHub username과 가입 이메일. 다음 단계와 권한 요청에 씁니다.

1.2프로젝트 저장소(repo) 권한 요청

우리 프로젝트는 github.com/D-W-Kim/CI-Course 에 있습니다. 고친 코드를 올리려면(push) 쓰기 권한이 필요합니다.

이렇게 요청하세요  원작자(Sam)에게 메시지로: "제 GitHub username은 OOO 입니다. D-W-Kim/CI-Course 저장소에 Collaborator(쓰기) 권한 부탁드립니다." → 초대 수락 이메일이 오면 Accept를 누르면 끝.
⚠️권한이 없어도 받기는 됩니다

이 저장소는 공개라 clone(받기)·pull(갱신)은 권한 없이도 가능합니다. 다만 push(올리기)는 Collaborator 권한이 있어야 하니, 배포까지 하려면 1.2를 꼭 완료하세요.

02

도구 3가지 설치하기

약 20분

Git · Node.js · (선택)VS Code. 모두 "다음 → 다음"으로 설치되는 일반 프로그램입니다. 딱 한 번만 깔면 됩니다.

2.1Git 설치 — 버전관리 도구

  1. git-scm.com/download/win 에서 64-bit 설치 파일 다운로드
  2. 실행 후 옵션은 전부 기본값으로 Next 눌러 설치 (바꿀 것 없습니다)
  3. 설치 후 PowerShell을 새로 열어 확인:
# 버전 번호가 나오면 설치 성공
git --version
git version 2.47.0.windows.1

2.2Node.js 설치 — 프로젝트 실행 엔진

이 프로젝트는 Node.js 20 버전이 필요합니다. npm(패키지 관리 도구)도 함께 깔립니다.

  1. nodejs.org 접속 → "LTS" 버전(왼쪽, 안정 버전) 다운로드
  2. "다음 → 다음"으로 설치
  3. PowerShell을 새로 열어 확인:
node --version
v20.18.0
npm --version
10.8.2
💡v20이 아니어도 v20 이상이면 보통 OK

숫자가 v20 또는 v22처럼 나오면 됩니다. 명령이 "인식되지 않습니다"라고 나오면 PowerShell 창을 완전히 닫았다 다시 여세요. 설치 직후엔 새 창에서만 인식됩니다.

2.3Git 최초 1회 설정

내가 누구인지 Git에 알려줍니다. (커밋에 이름표로 들어갑니다. GitHub 가입 정보와 같게 적으세요.)

git config --global user.name "홍길동"
git config --global user.email "my-email@example.com"

2.4(선택) VS Code — 코드 편집기

꼭 필요하진 않지만, 코드를 눈으로 보기 편합니다. code.visualstudio.com 에서 설치하면 됩니다.

03

Claude Code 준비하기

약 15분

코드를 직접 외워 짤 필요 없이, 한국어로 부탁하면 고쳐주는 AI 도우미를 설치합니다.

3.1Claude 계정 만들기

  1. claude.ai 접속 → Google 계정 또는 이메일로 가입
  2. Claude Code를 원활히 쓰려면 Claude Pro(또는 Max) 구독을 권장합니다. (회사에서 계정/요금제를 제공한다면 그 안내를 따르세요.)
💳요금제는 회사 정책 확인

구독 결제 전, 회사에서 지원하는 Claude 계정이나 API 키가 있는지 먼저 확인하세요. 원작자(Sam)에게 물어보면 됩니다.

3.2Claude Code 설치

PowerShell에 아래를 붙여넣습니다. -g는 "컴퓨터 전체에서 쓸 수 있게 설치"라는 뜻입니다.

npm install -g @anthropic-ai/claude-code

3.3실행하고 로그인

아무 폴더에서나 claude 라고 치면 실행됩니다. 처음 실행하면 로그인 안내가 뜹니다.

claude
# 안내에 따라 브라우저가 열리면 Claude 계정으로 로그인 → 인증 완료
🔗버전은 계속 바뀝니다

설치/로그인 방식이 바뀌면 공식 문서를 보세요 → docs.claude.com/en/docs/claude-code. 종료는 /exit 또는 Ctrl + C 입니다.

04

프로젝트 내려받기

약 10분

드디어 코드를 내 컴퓨터로 가져옵니다. 처음엔 clone(통째 복제), 이후엔 pull(최신만 갱신)입니다.

4.1작업 폴더 정하기

받을 위치를 정합니다. 경로에 한글·공백이 없는 영어 폴더를 권장합니다(도구 오류가 적습니다). 예: C:\Work

# C 드라이브에 Work 폴더를 만들고 그 안으로 이동
mkdir C:\Work
cd C:\Work

4.2복제하기 (clone)

git clone https://github.com/D-W-Kim/CI-Course.git
# → C:\Work\CI-Course 폴더가 생깁니다

받은 뒤, 우리가 실제로 작업할 메인 프로젝트 폴더로 이동합니다:

cd CI-Course\projects\cost-sim-v2.1
왜 이 폴더인가요?  저장소 안에는 여러 버전이 있지만, 현재 살아있는(라이브) 버전은 projects/cost-sim-v2.1 입니다. 앞으로 모든 명령은 이 폴더 안에서 실행합니다.

4.3나중에 최신 받기 (pull)

다른 사람이(또는 원작자가) 코드를 바꿨을 수 있습니다. 작업을 시작하기 전엔 항상 최신을 당겨받으세요.

# CI-Course 폴더 안 어디서든
git pull
🔐AWS 키 파일은 별도로 받으세요

AWS 접속에 쓰는 sam-cli_accessKeys.csv 같은 비밀 파일은 보안상 GitHub에 올라가 있지 않습니다(이미 차단 설정됨). 원작자에게 이메일·메신저 등 별도 채널로 받아 CI-Course 폴더에 두세요. 이 파일은 절대 push하면 안 됩니다.

05

내 컴퓨터에서 실행해 보기

약 10분

고치기 전에, 사이트가 내 컴퓨터에서 정상으로 뜨는지 먼저 확인합니다. 이게 되면 환경 세팅은 성공입니다.

5.1부품(라이브러리) 설치 — npm ci

프로젝트가 쓰는 외부 부품들을 한 번에 내려받습니다. 처음 1회, 그리고 부품 목록이 바뀌었을 때 실행합니다. (몇 분 걸릴 수 있어요.)

# 반드시 cost-sim-v2.1 폴더 안에서
npm ci

5.2개발 서버 켜기 — npm run dev

npm run dev
▲ Next.js 14.2.15
- Local:  http://localhost:3000

브라우저를 열고 주소창에 http://localhost:3000 을 입력하세요. 게임 화면이 뜨면 성공입니다 🎉

⏹️서버 끄기

실행 중인 PowerShell 창에서 Ctrl + C 를 누르면 서버가 꺼집니다. 다시 켜려면 npm run dev 를 또 입력하면 됩니다.

06

Claude Code로 수정하고 빌드

핵심

이제 진짜 수정·보완 작업입니다. 코드를 직접 짜는 게 아니라, AI에게 한국어로 부탁하고 결과를 확인합니다.

6.1Claude Code 켜기

# cost-sim-v2.1 폴더 안에서 실행해야 이 프로젝트를 이해합니다
cd C:\Work\CI-Course\projects\cost-sim-v2.1
claude

6.2한국어로 부탁하기

그냥 하고 싶은 걸 말로 적으면 됩니다. Claude가 관련 파일을 찾아 고쳐줍니다.

> 메인 화면의 게임 제목을 "개발원가 워게임"으로 바꿔줘
> 라운드 제한시간 기본값을 10분에서 12분으로 바꿔줘
> 시작 버튼 색을 더 진한 초록색으로 바꿔줘
> 방금 바꾼 내용 빌드해서 문제없는지 확인해줘
🤝Claude가 명령어도 대신 실행해 줍니다

아래 6.3의 검증 명령(npm run build 등)을 외우기 부담스러우면, Claude에게 "빌드해서 통과하는지 확인해줘" 라고 부탁하세요. Claude가 직접 실행하고 결과를 알려줍니다. 파일을 바꾸기 전에는 무엇을 바꿀지 먼저 보여주고 승인을 받습니다.

6.3바꾼 뒤 3종 점검 (중요)

코드를 바꿨으면 올리기 전에 이상 없는지 꼭 확인합니다. 셋 다 통과해야 안전합니다.

npm run typecheck   # 타입 오류 검사 (0 errors 목표)
npm test            # 자동 테스트 (전부 PASS 목표)
npm run build       # 실제 배포용 빌드가 되는지 (Compiled 성공)
⛔여기는 건드리지 마세요 — lib/cost-engine/

원가를 계산하는 핵심 로직입니다. 27개의 "정답 검증(골든 픽스처)"이 걸려 있어, 잘못 손대면 게임 채점이 틀어집니다. Claude에게도 "lib/cost-engine 폴더는 수정하지 말고 진행해줘" 라고 미리 일러두세요.

07

저장하고 배포하기

약 5분 + 빌드 대기

고친 내용을 GitHub에 올리면 끝입니다. 그 다음은 AWS가 자동으로 라이브 사이트에 반영합니다.

7.1변경 저장 (add → commit)

# 1) 바뀐 파일 전부 담기
git add .

# 2) 무엇을 바꿨는지 설명을 붙여 한 묶음으로 저장
git commit -m "제목 문구 수정 및 제한시간 12분으로 변경"

7.2올리기 (push)

git push
여기서 자동 배포가 시작됩니다  master 브랜치에 push되면 AWS Amplify가 변경을 감지해 알아서 빌드하고 라이브에 반영합니다. 보통 몇 분 걸립니다.

7.3배포 확인

  • 라이브 사이트에서 결과 확인 → master.d3arok48ln7jvp.amplifyapp.com
  • 진행 상태가 궁금하면 AWS Amplify 콘솔에서 빌드 로그를 볼 수 있습니다 (앱 ID d3arok48ln7jvp).
⚠️처음 push할 때

GitHub 로그인 창이 뜰 수 있습니다. GitHub 계정으로 로그인하면 이후엔 기억됩니다. "권한 없음(403)" 오류가 나면 Fork 레포(`D-W-Kim/CI-Course`)에 push 권한이 있는지 확인하세요.

🚫절대 금지: git push --force

다른 사람의 작업을 덮어쓰며 이력을 망가뜨릴 수 있습니다. 이 명령은 절대 사용하지 마세요.

09

자주 막히는 곳 & 해결

대부분의 문제는 아래 표로 해결됩니다. 그래도 안 되면 11번 섹션의 연락처로 문의하세요.

git / node가 "인식되지 않습니다"설치 직후라 창이 모름PowerShell 창을 닫았다 새로 열기. 그래도 안 되면 재부팅.
개발 서버가 이상하게 동작임시 캐시(.next) 오염Remove-Item -Recurse -Force .next 후 npm run dev 다시
npm ci 오류Node 버전 안 맞음 / 부품 목록 변경Node가 v20 이상인지 확인, 다시 npm ci
push할 때 권한 거부 (403)저장소 쓰기 권한 없음01.2 Collaborator 권한 받았는지 원작자에게 확인
git pull 시 충돌(conflict)같은 부분을 동시에 수정혼자 해결하지 말고 Claude에게 "pull 충돌 해결해줘" 부탁 또는 원작자 문의

보안 · 절대 금지 5계명

딱 다섯 가지만 지키면 사고는 거의 없습니다. 헷갈리면 멈추고 물어보세요.

1️⃣비밀 파일을 올리지 않는다

sam-cli_accessKeys.csv, .env 같은 키·비밀번호 파일은 절대 commit/push 금지. (다행히 이미 자동 차단 설정돼 있지만, 새 비밀 파일을 만들면 주의하세요.)

2️⃣원가 엔진을 함부로 고치지 않는다

lib/cost-engine/는 채점의 심장입니다. 수정이 꼭 필요하면 원작자와 상의하고, 반드시 npm test 27개 통과를 확인하세요.

3️⃣git push --force 를 쓰지 않는다

이력을 파괴하는 명령입니다. 어떤 경우에도 사용하지 마세요.

4️⃣outputs/ 폴더를 임의로 지우지 않는다

최종 산출물 결재함입니다. 삭제·덮어쓰기는 승인 후에만.

5️⃣막히면 멈추고 묻는다

"이거 올려도 되나?" 싶으면 push 전에 물어보세요. 되돌리는 것보다 묻는 게 훨씬 쉽습니다.
